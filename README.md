# vc-rln: rate limits derived from verifiable credentials

Code, data and analysis for the paper *"Anonymous Social Media Posting with Rate Limits Derived from Verifiable
Credentials"*, V. Rathore and M. K. Rawat, submitted to the 3rd International Conference on Computer, Communication
and Control (IC4'27), Medicaps University, Indore, India.

A member posts anonymously in a community and proves in zero knowledge that a leaf of the issuer's Merkle tree
commits to its credential, and that its message index is below a limit the proof computes from the hidden
credential attributes and the community's anchored policy. Exceeding the limit reveals the member's secret, as in
the rate-limiting nullifier (RLN). This repository holds the circuit, the contracts, every measurement script, the
raw data behind each table and figure, the analysis that computes every number in the paper, the proving and
verification keys of the two depth-20 circuits, and read-only tools that check the on-chain results. All
transactions were sent on public test networks, so each can be checked on a block explorer.

## Check the results (no keys, no transactions)

Requires Node.js 20 or later (the measurements used 22.10.0) and Python 3.12 with matplotlib 3.10.5
(`pip install -r analysis/requirements.txt`). On macOS use `shasum -a 256 -c` instead of `sha256sum -c`.

```bash
npm ci
(cd data && sha256sum -c SHA256SUMS)   # the data the numbers were computed from (first: later steps rewrite files)
npm test                               # 49 circuit and client checks, 11 registry checks; rewrites data/tests_*.json
node tools/verify_proofs.js            # sample proofs verify; a reused index reveals the secret
node tools/verify_transactions.js      # all 205 cited receipts exist, succeeded and used the reported gas
node tools/rebuild_tree.js             # each gas-run registry's tree, rebuilt from events, reproduces every root
bash analysis/run_all.sh               # recomputes data/paper_numbers.json, the tables and the figures
git status --short                     # only data/tests_*.json (new date) should differ
```

The tools use public RPC endpoints and retry when one fails; set `SEPOLIA_RPC`, `OP_RPC` or `ARB_RPC` to use
others. `rebuild_tree.js` needs endpoints that serve old logs (the defaults do; some free endpoints return
"pruned history"). To rerun one network: `node tools/rebuild_tree.js arbSepolia`.

The proving keys can be checked against the circuits and the phase-1 file:

```bash
mkdir -p ptau && curl -fL -o ptau/ppot_0080_15.ptau https://pse-trusted-setup-ppot.s3.eu-central-1.amazonaws.com/pot28_0080/ppot_0080_15.ptau
echo "4a8eb5a754ed4710d6ad603c2e1a89c72325a448e4474f8694d2c71c7c272f3d  ptau/ppot_0080_15.ptau" | sha256sum -c -
node node_modules/snarkjs/build/cli.cjs zkey verify build/vcrln_d20/c.r1cs ptau/ppot_0080_15.ptau build/vcrln_d20/c.zkey
node node_modules/snarkjs/build/cli.cjs zkey verify build/rln2_d20/c.r1cs ptau/ppot_0080_15.ptau build/rln2_d20/c.zkey
```

The independent credential check has its own pinned dependencies:

```bash
cd vc_check && npm ci && npm run check   # Digital Bazaar vc 7.3.0 + eddsa-jcs-2022 1.0.0, jsonld 9.0.0
```

It verifies the credential's signature against the issuer's did:ethr document on OP Sepolia, expands the credential
in JSON-LD safe mode, shows that the same credential without the undefined-terms context fails that expansion, and
writes `vc_check/result.json`. Registry status is checked by our client (`scripts/vc_demo.js`), not by this script.

## Rebuild and rerun

- Circuits: `bash scripts/build.sh` needs circom 2.2.3 on the PATH (or `CIRCOM=<path>`); it downloads and checks the
  phase-1 file. Phase 2 draws fresh randomness, so the new keys differ from the published ones, and the script
  overwrites `build/vcrln_d20` and `build/rln2_d20`. Afterwards rerun `EXPORT_PROOFS=1 bash analysis/run_all.sh` and
  regenerate `contracts/PostVerifier.sol` with `snarkjs zkey export solidityverifier`, or restore the published build
  with `git checkout build`. `node scripts/constraint_breakdown.js` (also needs circom) recomputes
  `data/constraint_breakdown.json`.
- CPU measurements: `bash scripts/run_cpu_suite.sh` runs only on Windows (Git Bash with PowerShell). It waits for an
  idle machine on mains power, runs every timed step and logs power and processor speed. Chrome runs use
  puppeteer-core from `npm ci` and Chrome at its default path unless `CHROME` is set. Absolute times hold for the
  machine and session; the paper compares circuits by paired runs.
- Testnet runs send transactions and append to the cited data files (the analysis then uses the newest complete run),
  so run them in a separate copy. Copy `.env.example` to `.env`, set a testnet-only key and RPC URLs, run
  `npx hardhat compile`, then `NET=opSepolia node scripts/testnet.js` and `NET=opSepolia node scripts/revoke_lag.js`,
  and, after an OP Sepolia `testnet.js` run with the same key, `node scripts/vc_demo.js`. The scripts never print
  the key, and they mask RPC URLs and long hex strings in error messages.

## Notes on the data

- `analysis/sessions.json` names the benchmark session the paper cites (27 October 2026, idle laptop on mains
  power) and the sessions left out, with the reason for each. An earlier session that ran mostly on battery is
  reported in the paper as a replication of the paired overhead.
- Mainnet fees come from oracle readings, not from transactions; `analysis/fees.py` fixes the window the paper uses.
- `scripts/gas_local.js` draws random leaves and proofs, so a rerun can differ from `data/gas_local.jsonl` by
  12 gas per zero calldata byte (tens of gas per transaction).
- `contracts/PostBoard.sol` refuses `x = 0`: the share would then equal the secret, and `shareX` would record the
  nullifier as unused. The check was added after the testnet runs, so the deployed baseline lacks it; its posts used
  341,979 to 342,015 gas on OP Sepolia, against 342,011 and 342,035 on the Hardhat EVM with the check.
- `data/superseded/` keeps the runs of an earlier registry version that the paper does not use.
- `data/tests_circuit.json` and `data/tests_registry.json` list every check with its expected and observed result.

## Security notes

- This is a research prototype. The setup used one local phase-2 contribution, which is enough for measurement but
  not for deployment. The tests exercise the honest witness generator and do not prove that no signal is
  under-constrained.
- The client rules in `scripts/lib.js` assume a client the issuer does not control, a node the member trusts, and an
  epoch taken from the chain head; Section VI of the paper lists the remaining limitations.
- Use only a testnet key in `.env`. The sample credential and proofs are test material.

## Research ethics and privacy

All transactions were sent on public test networks from test accounts created for this study; the mainnet data are
read-only samples of public fee fields. No personal data are collected; the credentials and members in the data are
synthetic. Blockchain addresses are pseudonymous public data. `data/bench_env.jsonl` records the processes that used
the most CPU while the benchmarks ran, as evidence of the machine's load.
